# 04 · 训练方法与配置

## 一、三种运行模式

Match3 Agent 在三种模式下运行，通过 `Match3Agent.FixedUpdate` 里的判断切换（见文档 01）：

| 模式 | 触发条件 | 更新方式 | 用途 |
| --- | --- | --- | --- |
| **训练** | 连接了 Python 训练器（`Academy.IsCommunicatorOn`） | `FastUpdate()` | 用 PPO 训练策略 |
| **CI / 覆盖模型** | `ModelOverrider.HasOverrides` | `FastUpdate()` | 自动化回归测试 |
| **推理 / 演示** | 以上都不是（Editor 里直接播放） | `AnimatedUpdate()` | 带动画观看、人工检查 |

`FastUpdate` 不播动画、一次算完所有连锁并立即请求下一步决策，因此训练吞吐远高于动画模式。

---

## 二、训练算法：PPO + 动作屏蔽

Match3 使用 **PPO**（`trainer_type: ppo`），奖励为"消除得分 × 0.01"。它没有用 SAC/好奇心/模仿等，
因为：

- 奖励**稠密**（几乎每步消除都有分），无需内在激励；
- 动作空间虽大，但**动作屏蔽**已把无效动作剔除，探索难度大幅下降；
- 任务是"固定步数最大化总分"，标准 on-policy PPO 即可。

**动作屏蔽对训练的意义**：策略网络的离散动作分布在采样前会先应用 mask，非法动作概率置零。
这让智能体**只在合法交换中学习**，等价于把巨大的动作空间实时裁剪到"当前可行解集合"，是本示例高效训练的关键。

## 三、配置文件解读（`config/ppo/Match3.yaml`）

```1:24:config/ppo/Match3.yaml
default_settings:
  trainer_type: ppo
  hyperparameters:
    batch_size: 16
    buffer_size: 120
    learning_rate: 0.0003
    beta: 0.005
    epsilon: 0.2
    lambd: 0.99
    num_epoch: 3
    learning_rate_schedule: constant
  network_settings:
    normalize: true
    hidden_units: 256
    num_layers: 4
    vis_encode_type: match3
  reward_signals:
    extrinsic:
      gamma: 0.99
      strength: 1.0
  keep_checkpoints: 5
  max_steps: 5000000
  time_horizon: 128
  summary_freq: 10000
```

### 关键字段说明

| 字段 | 值 | 解读 |
| --- | --- | --- |
| `trainer_type` | `ppo` | 采用 PPO |
| `batch_size` / `buffer_size` | 16 / 120 | 都很小——因为每步"落一子"就是一条经验，节奏快、单步信息量大 |
| `network_settings.num_layers` | 4 | 相对较深，应对棋盘组合的复杂度 |
| `vis_encode_type` | **`match3`** | 使用专门的 `SmallVisualEncoder`（源自 Candy Crush 论文的小型 CNN），处理 `Rows×Cols×Channels` 的伪图像观测 |
| `normalize` | true | 归一化观测 |
| `max_steps` | 5,000,000 | 训练总步数 |
| `time_horizon` | 128 | 优势估计的时间视界 |

> `vis_encode_type: match3` 与 `Match3ObservationType` 的视觉形态配套：当传感器输出
> `Rows×Cols×Channels` 张量时，用这个小型 CNN 编码；即使是向量观测，该编码器设置也不影响向量路径。

### `default_settings` vs `behaviors`

- **`default_settings`**：给**所有 behavior** 的默认参数（真正用于训练模型时的设置）。
- **`behaviors`** 里的 `Match3SimpleHeuristic` / `Match3SmartHeuristic`：

```26:48:config/ppo/Match3.yaml
behaviors:
  Match3SimpleHeuristic:
    # Settings can be very simple since we don't care about actually training the model
    trainer_type: ppo
    hyperparameters:
      batch_size: 16
      buffer_size: 120
    network_settings:
      hidden_units: 4
      num_layers: 1
    max_steps: 5000000
    summary_freq: 10000
  Match3SmartHeuristic:
    ...（同样极简）
```

这两个 behavior 的网络被故意设得极小（`hidden_units: 4`），因为**它们根本不打算训练出好模型**——
它们对应场景里 `ForceHeuristic = true` 的 Agent，动作完全由启发式（随机合法 / 贪心）产生。
它们存在的目的是：**在 TensorBoard 里记录启发式的得分曲线，作为训练模型的对照基线**。

## 四、启发式基线对照

结合文档 03 的启发式实现，三条曲线可对照：

| Behavior | 动作来源 | `EvalMovePoints` | 期望表现 |
| --- | --- | --- | --- |
| `Match3SimpleHeuristic` | 合法 move 中随机 | 恒为 1（基类默认） | 最低基线 |
| `Match3SmartHeuristic` | 贪心最大化本步得分 | 真实计分（`Match3ExampleActuator`） | 中等基线（无长远规划） |
| 训练模型（`default_settings`） | PPO 学到的策略 | — | 应超过贪心（会为连锁做规划） |

`Match3ActuatorComponent.ForceHeuristic` 控制是否强制走 `Heuristic()`：

```39:50:com.unity.ml-agents/Runtime/Integrations/Match3/Match3ActuatorComponent.cs
        [HideInInspector, SerializeField, FormerlySerializedAs("ForceHeuristic")]
        [Tooltip("Force using the Agent's Heuristic() method to decide the action. This should only be used in testing.")]
        bool m_ForceHeuristic;

        public bool ForceHeuristic
        {
            get => m_ForceHeuristic;
            set => m_ForceHeuristic = value;
        }
```

## 五、训练与推理流程

### 5.1 启动训练

```bash
mlagents-learn config/ppo/Match3.yaml --run-id=match3_run
```

- 打开 `Project` 中的 `Match3` 场景，命令行提示后按 Play。
- Agent 的 `BehaviorParameters.BehaviorName` 需与要训练的 behavior 对应
  （训练模型的 Agent 用 `default_settings` 覆盖的行为名；两个 Heuristic Agent 用各自行为名产出基线）。

### 5.2 观察指标

- TensorBoard 中对比三条 `Environment/Cumulative Reward` 曲线（模型 vs 两种启发式）。
- 期望：训练模型最终**超过 SmartHeuristic**，因为神经网络能为"连锁/保留高价值特殊格"做多步规划，
  而贪心只看当前一步。

### 5.3 导出与本地推理

- 训练产出 `.onnx`（示例已附 `TFModels/Match3VectorObs.onnx`、`Match3VisualObs.onnx`）。
- 把模型拖到 `BehaviorParameters.Model`，`BehaviorType` 设为 `Default` 或 `InferenceOnly`，
  即可脱离 Python 本地推理运行（此时走 `AnimatedUpdate` 带动画展示）。

## 六、把你自己的三消游戏接入（复用指南）

Match3 集成层是**通用**的。要接入自己的三消类游戏，只需：

1. **实现 `AbstractBoard`**：提供 `GetMaxBoardSize`、`GetCurrentBoardSize`、`GetCellType`、
   `GetSpecialType`、`IsMoveValid`、`MakeMove`。合法性判定可直接用基类的 `SimpleIsMoveValid`。
2. **挂组件**：在 Agent GameObject 上加 `Match3SensorComponent` + `Match3ActuatorComponent`
   （或其子类）+ `BehaviorParameters`。它们会自动 `GetComponent<AbstractBoard>()` 找到你的棋盘。
3. **驱动决策**：参考 `Match3Agent`，在合适时机 `RequestDecision()`，并在得分处 `AddReward()`。
4. **（可选）自定义启发式**：继承 `Match3Actuator` 重写 `EvalMovePoints`，得到更强的对照基线。
5. **写训练配置**：复制 `config/ppo/Match3.yaml`，行为名对齐 `BehaviorParameters.BehaviorName`。

> 核心复用点：**你只需写游戏规则（`AbstractBoard`），观测编码、动作编码、动作屏蔽、启发式全部由 SDK 提供**。

## 七、全篇总结

Match3 示例系统性回答了"**如何把一个非标准（棋盘、回合、离散大动作空间）游戏接入强化学习**"：

- **解耦**：`AbstractBoard` 作为唯一契约，隔离游戏逻辑与 ML-Agents。
- **观测**：one-hot 编码 + 向量/视觉双形态 + 变长补零。
- **动作**：`Move` 索引编解码 + 单分支离散 + **动作屏蔽**裁剪无效解。
- **节奏**：状态机 + Fast/Animated 双更新 + 自数步数手动截断。
- **训练**：PPO + 稠密得分奖励，并用两档启发式做基线对照。
