# 03 · 观测与动作空间

本篇讲清 Match3 最有技术含量的两点：**观测怎么编码**、**动作怎么编解码与屏蔽**。

---

## 一、观测空间（Match3Sensor）

### 1.1 两个传感器：颜色 + 特殊类型

`Match3SensorComponent.CreateSensors()` 会创建**最多两个** `Match3Sensor`：

```42:59:com.unity.ml-agents/Runtime/Integrations/Match3/Match3SensorComponent.cs
        public override ISensor[] CreateSensors()
        {
            // Clean up any existing sensors
            Dispose();

            var board = GetComponent<AbstractBoard>();
            if (!board)
            {
                return Array.Empty<ISensor>();
            }
            var cellSensor = Match3Sensor.CellTypeSensor(board, m_ObservationType, m_SensorName + " (cells)");
            // This can be null if numSpecialTypes is 0
            var specialSensor = Match3Sensor.SpecialTypeSensor(board, m_ObservationType, m_SensorName + " (special)");
            m_Sensors = specialSensor != null
                ? new ISensor[] { cellSensor, specialSensor }
            : new ISensor[] { cellSensor };
            return m_Sensors;
        }
```

- **cellSensor**：编码每格的**颜色类型**，one-hot 大小 = `NumCellTypes`。
- **specialSensor**：编码每格的**特殊类型**，one-hot 大小 = `NumSpecialTypes + 1`（+1 是"普通"那一档）。
  若 `NumSpecialTypes == 0`，`SpecialTypeSensor` 返回 `null`，只保留一个传感器。

### 1.2 GridValueProvider：优雅的解耦委托

`Match3Sensor` 不直接调用 `board.GetCellType`，而是接收一个委托 `GridValueProvider gvp`：

- `CellTypeSensor` 传入 `board.GetCellType`；
- `SpecialTypeSensor` 传入 `board.GetSpecialType`。

这样**同一套编码逻辑**可以复用于"颜色"和"特殊类型"两种网格值，无需重复代码。

### 1.3 观测形态：向量 vs 视觉

由 `Match3ObservationType` 决定观测的 `ObservationSpec`：

```81:83:com.unity.ml-agents/Runtime/Integrations/Match3/Match3Sensor.cs
            m_ObservationSpec = obsType == Match3ObservationType.Vector
                ? ObservationSpec.Vector(maxBoardSize.Rows * maxBoardSize.Columns * oneHotSize)
                : ObservationSpec.Visual(maxBoardSize.Rows, maxBoardSize.Columns, oneHotSize);
```

| 形态 | 观测形状 | 说明 |
| --- | --- | --- |
| `Vector` | 一维，长度 `Rows × Columns × oneHotSize` | 每格 one-hot 拼平成长向量 |
| `UncompressedVisual` | `(Rows, Columns, oneHotSize)` | 把 one-hot 当作"图像通道"，喂 CNN |
| `CompressedVisual` | 同上，但训练时以 **PNG** 传输 | 每 3 通道压成一张 RGB 图，节省带宽 |

> 关键洞察：**即使是"视觉"观测，也不是截屏！** 而是把棋盘的 one-hot 张量排列成
> `Rows×Columns×Channels` 的"伪图像"。所以颜色数 = 通道数，而非 RGB 三通道。
> `Match3VectorObs` 与 `Match3VisualObs` 两个预制体就是这两种形态的对照。

### 1.4 变长棋盘：补零对齐

观测张量始终按 **`GetMaxBoardSize()`** 分配（形状固定，模型输入才固定），
但只有 `GetCurrentBoardSize()` 范围内写真实 one-hot，超出部分**写 0**：

```142:167:com.unity.ml-agents/Runtime/Integrations/Match3/Match3Sensor.cs
            for (var r = 0; r < currentBoardSize.Rows; r++)
            {
                for (var c = 0; c < currentBoardSize.Columns; c++)
                {
                    var val = m_GridValues(r, c);
                    writer.WriteOneHot(offset, r, c, val, m_OneHotSize, isVisual);
                    offset += m_OneHotSize;
                }

                for (var c = currentBoardSize.Columns; c < m_MaxBoardSize.Columns; c++)
                {
                    writer.WriteZero(offset, r, c, m_OneHotSize, isVisual);
                    offset += m_OneHotSize;
                }
            }

            for (var r = currentBoardSize.Rows; r < m_MaxBoardSize.Columns; r++)
            {
                for (var c = 0; c < m_MaxBoardSize.Columns; c++)
                {
                    writer.WriteZero(offset, r, c, m_OneHotSize, isVisual);
                    offset += m_OneHotSize;
                }
            }
```

这就是"固定尺寸的观测容器 + 当前尺寸的有效数据 + 补零"的经典变长处理法。

## 二、动作空间（Move + Match3Actuator）

### 2.1 动作 = "交换相邻两格" = 一个离散索引

三消的动作是"交换相邻两格"。`Move` 结构把它编码成一个整数 `MoveIndex`：

- 只枚举棋盘的**内部边**（相邻格之间的连线），每条边代表一次交换。
- **规范化**：只用 `Right` 和 `Up` 两个方向表示（Left/Down 会被转成相邻格的 Right/Up），避免重复计数。
- 动作总数：

```273:276:com.unity.ml-agents/Runtime/Integrations/Match3/Move.cs
        public static int NumPotentialMoves(BoardSize maxBoardSize)
        {
            return maxBoardSize.Rows * (maxBoardSize.Columns - 1) + (maxBoardSize.Rows - 1) * (maxBoardSize.Columns);
        }
```

即 `Rows×(Columns-1)`（横向边）+ `(Rows-1)×Columns`（纵向边）。例如 8×8 棋盘 = 8×7 + 7×8 = **112** 个动作。

动作空间声明为**单分支离散**，分支大小 = 该值（按 **Max** 尺寸算，保证动作维度固定）：

```65:78:com.unity.ml-agents/Runtime/Integrations/Match3/Match3ActuatorComponent.cs
        public override ActionSpec ActionSpec
        {
            get
            {
                var board = GetComponent<AbstractBoard>();
                if (board == null)
                {
                    return ActionSpec.MakeContinuous(0);
                }

                var numMoves = Move.NumPotentialMoves(board.GetMaxBoardSize());
                return ActionSpec.MakeDiscrete(numMoves);
            }
        }
```

### 2.2 动作解码与执行

Agent 输出一个 `moveIndex`，`Match3Actuator.OnActionReceived` 把它解码成 `Move` 并执行：

```47:58:com.unity.ml-agents/Runtime/Integrations/Match3/Match3Actuator.cs
        public void OnActionReceived(ActionBuffers actions)
        {
            m_Board.CheckBoardSizes(m_MaxBoardSize);
            if (m_ForceHeuristic)
            {
                Heuristic(actions);
            }
            var moveIndex = actions.DiscreteActions[0];

            Move move = Move.FromMoveIndex(moveIndex, m_MaxBoardSize);
            m_Board.MakeMove(move);
        }
```

### 2.3 动作屏蔽（Action Masking）——本示例精华

如果不加约束，112 个动作里绝大多数都是"交换后并不能三连"的无效动作，探索会非常低效。
`WriteDiscreteActionMask` 在每次决策前**把所有非法动作屏蔽掉**，只给策略留下能真正得分的交换：

```61:106:com.unity.ml-agents/Runtime/Integrations/Match3/Match3Actuator.cs
        public void WriteDiscreteActionMask(IDiscreteActionMask actionMask)
        {
            var currentBoardSize = m_Board.GetCurrentBoardSize();
            m_Board.CheckBoardSizes(m_MaxBoardSize);
            const int branch = 0;
            bool foundValidMove = false;
            using (TimerStack.Instance.Scoped("WriteDiscreteActionMask"))
            {
                var numMoves = m_Board.NumMoves();

                var currentMove = Move.FromMoveIndex(0, m_MaxBoardSize);
                for (var i = 0; i < numMoves; i++)
                {
                    // Check that the move is allowed for the current boardSize (e.g. it won't move a piece out of
                    // bounds), and that it's allowed by the game itself.
                    if (currentMove.InRangeForBoard(currentBoardSize) && m_Board.IsMoveValid(currentMove))
                    {
                        foundValidMove = true;
                    }
                    else
                    {
                        actionMask.SetActionEnabled(branch, i, false);
                    }
                    currentMove.Next(m_MaxBoardSize);
                }

                if (!foundValidMove)
                {
                    // If all the moves are invalid and we mask all the actions out, this will cause an assert
                    // later on in IDiscreteActionMask. Instead, fire a callback to the user if they provided one,
                    // (or log a warning if not) and leave the last action unmasked. This isn't great, but
                    // an invalid move should be easier to handle than an exception..
                    if (m_Board.OnNoValidMovesAction != null)
                    {
                        m_Board.OnNoValidMovesAction();
                    }
                    else
                    {
                        Debug.LogWarning(...);
                    }
                    actionMask.SetActionEnabled(branch, numMoves - 1, true);
                }
            }
        }
```

屏蔽逻辑做了两件事：

1. **越界屏蔽**：`InRangeForBoard(currentBoardSize)` 屏蔽掉那些会作用到"当前棋盘之外"的 move（变长棋盘需要）。
2. **规则屏蔽**：`IsMoveValid(move)` 屏蔽掉交换后无法形成三连的 move。
3. **兜底**：若一个合法 move 都没有（死局），为避免"全屏蔽"触发断言，会**保留最后一个动作**并回调
   `OnNoValidMovesAction`（否则打日志警告）。

### 2.4 合法性判定：SimpleIsMoveValid

`Match3Board.IsMoveValid` 直接用基类的 `SimpleIsMoveValid`：把一次交换拆成两个"半步"，
分别检查交换后该格在水平/垂直方向能否凑够 ≥3 连（`CheckHalfMove`）。只要任一半步成立即合法。

## 三、启发式策略（Heuristic / GreedyMove）

`Match3Actuator` 内置一个**贪心启发式**，用于无模型时的对照基线：

- `GreedyMove()` 遍历所有合法 move，取 `EvalMovePoints` 最高者；同分时用**蓄水池采样**均匀随机选一个。
- 基类 `Match3Actuator.EvalMovePoints` 默认恒返回 1 → 相当于"合法 move 里随机选"（对应 `Match3SimpleHeuristic`）。
- 示例子类 `Match3ExampleActuator.EvalMovePoints` **重写**为真实计分评估（含特殊格分值），
  于是变成"贪心最大化本步得分"（对应 `Match3SmartHeuristic`）。

```21:39:Project/Assets/ML-Agents/Examples/Match3/Scripts/Match3ExampleActuator.cs
        protected override int EvalMovePoints(Move move)
        {
            var pointsByType = new[] { Board.BasicCellPoints, Board.SpecialCell1Points, Board.SpecialCell2Points };
            // Counts the expected points for making the move.
            var moveVal = Board.GetCellType(move.Row, move.Column);
            var moveSpecial = Board.GetSpecialType(move.Row, move.Column);
            var (otherRow, otherCol) = move.OtherCell();
            var oppositeVal = Board.GetCellType(otherRow, otherCol);
            var oppositeSpecial = Board.GetSpecialType(otherRow, otherCol);


            int movePoints = EvalHalfMove(
                otherRow, otherCol, moveVal, moveSpecial, move.Direction, pointsByType
            );
            int otherPoints = EvalHalfMove(
                move.Row, move.Column, oppositeVal, oppositeSpecial, move.OtherDirection(), pointsByType
            );
            return movePoints + otherPoints;
        }
```

这三档（随机合法 / 贪心 / 训练模型）正好构成训练效果的对照，详见下一篇。

## 四、观测与动作维度小结

| 项目 | 计算式 | 8×8、6 色、2 特殊类型的例子 |
| --- | --- | --- |
