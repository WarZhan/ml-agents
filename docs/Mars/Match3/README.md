> 本报告深入分析 Unity ML-Agents 中的 **Match3（三消游戏）** 示例，重点讲解它如何把一个
> **非移动型、回合制的棋盘游戏**接入 ML-Agents 框架。Match3 是理解「自定义 Sensor / Actuator」
> 与「动作屏蔽（Action Masking）」的最佳范例。

> - 示例工程：`Project/Assets/ML-Agents/Examples/Match3/`

## 一句话总览

Match3 示例的核心价值在于展示：**当游戏的"状态"和"动作"都不是标准的向量/连续量时，
如何通过实现 `AbstractBoard` 抽象类，把游戏逻辑与 ML-Agents 的 Sensor/Actuator 解耦对接**，
并用**动作屏蔽**把"棋盘上所有合法交换"约束到策略输出上。

```
┌─────────────────────────────────────────────────────────────────┐
│                      Match3 Agent (Unity)                       │
│                                                                 │
│   ┌──────────────┐   观测   ┌─────────────┐  动作+屏蔽           │
│   │ Match3Sensor  │◄────────│             │◄──────┐             │
│   │(cells/special)│         │ Match3Board │       │             │
│   └──────────────┘          │ : Abstract  │   ┌────┴─────────┐  │
│   ┌──────────────┐ MakeMove │   Board     │   │Match3Actuator│  │
│   │ Match3Drawer │◄─────────│             │──►│ (Move 编解码) │  │
│   │ (可视化)      │          └─────────────┘   └──────────────┘  │
│   └──────────────┘                                              │
└─────────────────────────────────────────────────────────────────┘
        │                                              │
   PPO 训练 (远程)                              导出 .onnx 本地推理
```

## 关键特性速览

- **自定义棋盘接入**：`Match3Board : AbstractBoard`，只实现 6 个抽象方法即可接入。
- **观测**：把棋盘每格的"颜色类型 + 特殊类型"做 **one-hot 编码**，支持向量 / 视觉两种形态。
- **动作**：把"交换相邻两格"编码为 **1 个离散分支**，动作数 = 棋盘内部边数。
- **动作屏蔽**：每步用 `IsMoveValid` 屏蔽所有不能构成三连的交换，大幅缩小探索空间。
- **变长棋盘**：支持每回合随机棋盘尺寸，用 `GetMaxBoardSize` / `GetCurrentBoardSize` + 补零处理。
- **显式状态机**：Agent 用状态机推进"找匹配→消除→下落→填充→请求决策"的三消循环。
