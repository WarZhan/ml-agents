# 项目概述

## 一、项目简介

本仓库是 **Unity ML-Agents Toolkit**（Unity 机器学习智能体工具包），一个开源项目，
用于将 Unity 游戏与仿真场景作为环境来训练智能体（Agent）。它提供基于 PyTorch 的多种
强化学习/模仿学习算法实现，使游戏开发者与研究者能够方便地训练 2D/3D/VR/AR 场景下的
智能体，用于 NPC 行为控制、自动化测试、游戏设计评估等。

- Unity 编辑器版本：`2022.3.62f2`（见 `Project/ProjectSettings/ProjectVersion.txt`）
- 许可证：Apache License 2.0

## 二、整体框架

ML-Agents 由两大端组成，通过 gRPC/Protobuf 通信：

1. **Unity 端（C# SDK）**：在场景中定义 `Agent`，负责采集观测（Observation）、
   执行动作（Action）、计算奖励（Reward）。运行时由 `Academy` 统一调度。
2. **Python 端（训练器）**：通过 `mlagents-learn` 启动，使用以下算法训练：
   - **PPO**（Proximal Policy Optimization，近端策略优化）：默认的在策略强化学习算法。
   - **SAC**（Soft Actor-Critic，软演员-评论家）：离策略强化学习算法，样本利用率更高。
   - **MA-POCA**（Multi-Agent POsthumous Credit Assignment，多智能体事后信用分配）：
     面向多智能体协作的算法，可处理组奖励与中途退出的智能体。
   - **自对弈（Self-Play）**：让智能体与自身历史版本对抗，用于对抗性多智能体场景。

   并支持两种模仿学习（Imitation Learning）算法：
   - **BC**（Behavioral Cloning，行为克隆）：直接模仿专家演示数据的动作。
   - **GAIL**（Generative Adversarial Imitation Learning，生成对抗模仿学习）：
     通过判别器学习专家行为的奖励信号。

训练完成后导出 `.onnx`/`.nn` 模型，由 Unity 的 **Inference Engine（Barracuda/Sentis）**
在本地跨平台推理运行（无需 Python）。

```
[Unity 场景 / Agent] <--gRPC/Protobuf--> [Python 训练器 mlagents]
        |                                          |
   采集观测、执行动作、奖励                    PPO / SAC / POCA / 模仿学习
        |                                          |
   导出 .onnx / .nn  ---->  Unity Inference Engine 本地推理
```

## 五、Demo 项目说明（按目录）

> 每个目录都是一个独立的 Demo（示例项目）。下面除了给出任务规格（目标 / 奖励 / 观测动作）外，
> 还为每个 Demo 补充了**设计说明**，即**重要的类**与**核心设计思路**，便于理解代码结构与可复用模式。

### 通用设计模式（所有 Demo 共用）

在阅读单个 Demo 之前，先理解贯穿所有示例的通用设计模式，可以事半功倍：

- **`Agent` 生命周期**：所有可训练脚本都继承 `Unity.MLAgents.Agent`，并重写以下钩子：
  - `Initialize()`：缓存组件引用、获取 `Academy.Instance.EnvironmentParameters`（用于课程学习/域随机化）。
  - `OnEpisodeBegin()`：重置场景与智能体状态，是每回合的起点。
  - `CollectObservations(VectorSensor)`：写入向量观测（也可用 `RayPerceptionSensor`、`CameraSensor` 等组件式传感器自动采集）。
  - `OnActionReceived(ActionBuffers)`：接收动作并驱动物理，同时发放奖励（`AddReward`/`SetReward`）。
  - `Heuristic(in ActionBuffers)`：手动/键盘控制，用于调试与录制模仿学习演示。
- **观测–动作解耦**：观测既可写在 `CollectObservations` 里，也可完全交给挂在同一 GameObject 上的 **SensorComponent**；
  动作既可在 `OnActionReceived` 里处理，也可拆分到独立的 **ActuatorComponent**（见 Basic）。
- **EnvController 模式**：多智能体或复杂场景通常额外使用一个 `MonoBehaviour` 环境控制器
  （如 `PushBlockEnvController`、`SoccerEnvController`、`DungeonEscapeEnvController`）统一管理回合、计分与重置，
  智能体本身只负责“感知 + 动作”。
- **Settings 单例**：`*Settings`（如 `PushBlockSettings`、`SoccerSettings`）集中存放移动速度等可调参数，通过 `FindObjectOfType` 共享。
- **组奖励与多智能体组**：协作/对抗类 Demo 使用 `SimpleMultiAgentGroup` 注册一组智能体，并用 `AddGroupReward`/`EndGroupEpisode` 实现团队信用分配（配合 MA-POCA）。

### Basic（一维移动入门）
- **目标**：智能体在直线上左右移动，前往奖励最高的状态。
- **智能体数量**：1。
- **奖励**：每步 -0.01；到达次优状态 +0.1；到达最优状态 +1.0。
- **观测/动作**：1 个状态变量；1 个离散动作分支（左/不动/右）。
- **基准奖励**：0.93。
- **设计说明**：
  - **重要的类**：`BasicController`（`MonoBehaviour`，非 `Agent`）、`BasicSensorComponent`/`BasicSensor`、`BasicActuatorComponent`/`BasicActuator`。
  - **核心设计思路**：这是**唯一不直接继承 `Agent`** 的示例，用于演示“无侵入式接入”。逻辑主体 `BasicController` 只是普通脚本，
    观测由自定义 `SensorComponent` 生成、动作由自定义 `ActuatorComponent`（`ActionSpec.MakeDiscrete(3)`，把 0/1/2 映射为 停/左/右）注入，
    再回调 `BasicController.MoveDirection` 移动并计分。它还演示了 `WaitTimeInference()`：训练时每步 `RequestDecision`，
    推理时按 `timeBetweenDecisionsAtInference` 节流请求决策。

### 3DBall（3D 平衡球）
- **目标**：智能体顶部平台尽量长时间保持小球不掉落。
- **智能体数量**：12 个同构智能体共享同一 Behavior。
- **奖励**：每步保持 +0.1；球掉落 -1.0。
- **观测/动作**：8 维向量观测（方块旋转、球位置与速度）；2 个连续动作（X/Z 轴旋转）。
- **变体**：`3DBallHard`（5 维观测，更难）、`Visual3DBall`（视觉观测）。
- **基准奖励**：100。
- **设计说明**：
  - **重要的类**：`Ball3DAgent`、`Ball3DHardAgent`。
  - **核心设计思路**：最经典的“连续控制”入门示例。观测在 `CollectObservations` 中手写（平台旋转 + 球的相对位置与速度），
    动作是 2 维连续量（绕 X/Z 轴旋转），并在旋转前用 `if` 限制平台倾角避免翻转过度。奖励采用**稠密塑形**：每步保持 +0.1、掉落 -1 并 `EndEpisode()`。
    `useVecObs` 开关区分向量版与视觉版（`Visual3DBall` 关闭向量观测改用摄像机）；`SetBall()` 用 `EnvironmentParameters`（`mass`/`scale`）实现**域随机化**，是 3DBallHard 变体只用 5 维观测演示“更少信息更难学”的对照。

### GridWorld（网格世界）
- **目标**：在网格中导航到正确颜色的目标，避开障碍。
- **智能体数量**：9。
- **奖励**：每步 -0.01；到达正确目标 +1.0（结束）；错误目标 -1.0（结束）。
- **观测/动作**：视觉观测（俯视图）+ 目标信号（one-hot）；5 个离散动作（四向移动/不动），
  默认开启动作屏蔽（Action Masking）。
- **基准奖励**：0.8。
- **设计说明**：
  - **重要的类**：`GridAgent`、`GridArea`、`GridSettings`。
  - **核心设计思路**：演示三大特性——(1) **视觉观测**：用俯视相机 + `RenderTexture` 作为主观测，`WaitTimeInference()` 在决策前手动 `renderCamera.Render()` 保证画面最新；
    (2) **动作屏蔽（Action Masking）**：`WriteDiscreteActionMask` 根据智能体是否贴墙禁用会撞墙的动作，避免无效探索；
    (3) **目标条件（goal-conditioned）**：`GridGoal`（绿加号/红叉）通过独立的 `VectorSensorComponent` 以 one-hot 传给策略，同一网络按目标切换行为。
    移动用 `Physics.OverlapBox` 做碰撞检测，命中正确/错误目标分别 `SetReward(±1)` 并结束。

### PushBlock（推箱子）
- **目标**：把方块推到目标点。
- **智能体数量**：1（场景内多份并行）。
- **奖励**：达成目标 +5；每步 -1/MaxStep。
- **观测/动作**：射线感知（`RayPerceptionSensor`，检测墙/目标/方块）；7 个离散动作（前后 / 左右转 / 左右平移）。
- **附带**：`Demos/ExpertPushBlock.demo`（模仿学习数据）；含协作版 `PushBlockCollab` 场景。
- **基准奖励**：4.5。
- **设计说明**：
  - **重要的类**：`PushAgentBasic`、`PushBlockEnvController`、`PushBlockSettings`、`GoalDetect`（挂在方块上，触发目标）、`PushAgentCollab`（协作变体）。
  - **核心设计思路**：典型的“**Agent 负责动作、外部脚本负责判定**”分工。`PushAgentBasic` 只在 `OnActionReceived` 里把离散动作转成 `Rigidbody.AddForce`/`Rotate`，
    并施加 `-1/MaxStep` 的时间惩罚促使尽快完成；进球判定放在方块上的 `GoalDetect`，命中后回调 `PushAgentBasic.ScoredAGoal()` 加 5 分并 `EndEpisode`。
    `OnEpisodeBegin` 随机旋转整块区域 + 随机出生点（`GetRandomSpawnPos` 用 `Physics.CheckBox` 防重叠），`SetResetParameters` 用 `EnvironmentParameters` 随机地面摩擦/方块尺寸做域随机化。

### PushBlockWithInput（基于 Input System 的推箱子）
- **说明**：PushBlock 的变体，演示如何把 Unity **Input System** 与 ML-Agents 结合，
  让“同一套输入动作”既能驱动玩家手动控制，也能映射为智能体动作。
- **奖励**：达成目标 +5；每步 -1/MaxStep。
- **依赖**：`com.unity.inputsystem`，以及扩展包 `com.unity.ml-agents.extensions` 中的 Input 适配器。
- **设计说明**：
  - **重要的类**：`PushBlockWithInputAgentBasic`、`PushBlockWithInputPlayerController`（实现 `IInputActionAssetProvider`）、
    `PushBlockActions`（由 `.inputactions` 资产自动生成）、`GoalDetectWithInput`，以及扩展包中的 `InputActuatorComponent`。
  - **核心设计思路**：核心创新是**输入系统与动作空间的自动桥接**——玩家控制逻辑写在 `PushBlockWithInputPlayerController` 里（读取 `Movement.movement`、监听 `jump.performed`），
    与 ML-Agents 完全解耦；只需实现 `IInputActionAssetProvider.GetInputActionAsset()` 返回 InputActionAsset，扩展包的 `InputActuatorComponent`
    就会**根据 `.inputactions` 中定义的动作自动推导 Agent 的动作空间**，并在训练/推理时把网络输出重绑定到虚拟控制器上。因此 `PushBlockWithInputAgentBasic.OnActionReceived` 里几乎没有移动代码（只保留步惩罚），移动完全由输入管线完成，实现“一套输入，人机通用”。

### WallJump（翻墙）
- **目标**：利用方块翻越墙体到达目标。
- **智能体数量**：1，但绑定 3 个模型，按墙高在 `WallJumpAgent` 中切换策略。
- **奖励**：每步 -0.0005；到达目标 +1.0；跌落 -1.0。
- **观测/动作**：射线感知（检测 4 类物体）+ 自身位置 + 是否着地；4 个离散动作分支（前后、旋转、左右、跳跃）。
- **训练**：支持课程学习（`config/ppo/WallJump_curriculum.yaml`）。
- **基准奖励**：0.8。
- **设计说明**：
  - **重要的类**：`WallJumpAgent`、`WallJumpSettings`，配合 SharedAssets 的 `ModelOverrider`。
  - **核心设计思路**：演示**运行时按情境切换模型（多策略）**。`ConfigureAgent(config)` 依据随机墙高把三种预训练模型
    （`noWallBrain`/`smallWallBrain`/`bigWallBrain`）之一通过 `SetModel(behaviorName, brain)` 装载——小墙直接跳过，大墙则先推方块当垫脚。
    跳跃通过自定义 `Jump()` + `MoveTowards()` 手动插值实现（并加 `fallingForce` 让下落更“实”），着地检测封装在 `DoGroundCheck`（`OverlapBox`/`Raycast` 两种精度）。该 Demo 是课程学习的典型案例：墙高作为课程参数逐步增大。

### Crawler（四足爬行者）
- **目标**：带 4 大腿 4 小腿的生物朝目标方向移动而不跌倒。
- **智能体数量**：10。
- **奖励**：几何型奖励（身体速度对齐目标速度 × 头部朝向对齐）。
- **观测/动作**：各肢体位姿/速度/角速度/是否着地等；20 个连续动作（8 关节目标旋转 + 8 关节力度）。
- **基准奖励**：3000。
- **设计说明**：
  - **重要的类**：`CrawlerAgent`，依赖 SharedAssets 的 `JointDriveController` + `BodyPart`、`OrientationCubeController`、`DirectionIndicator`。
  - **核心设计思路**：关节角色控制的**通用范式**（与 Worm/Walker 共享）。`JointDriveController` 把每个肢体封装成 `BodyPart`，
    `SetJointTargetRotation`/`SetJointStrength` 把 \([-1,1]\) 动作映射到 `ConfigurableJoint` 的目标旋转与驱动力，实现“肌肉式”PD 控制。
    观测全部在 **`OrientationCubeController` 稳定参考系**下计算（`InverseTransformDirection`），避免 ragdoll 抖动导致观测系混乱。
    奖励是**几何塑形**：`matchSpeedReward`（平均速度贴合目标速度的 sigmoid 型曲线）× `lookAtTargetReward`（朝向点积归一化），
    每回合随机目标速度以提升泛化。

### Worm（蠕虫）
- **目标**：带头部 + 3 节身体的蠕虫朝目标方向移动。
- **智能体数量**：10。
- **奖励**：几何型（身体速度/朝向对齐目标）。
- **观测/动作**：各体节位姿/速度；9 个连续动作（关节目标旋转）。
- **基准奖励**：800。
- **设计说明**：
  - **重要的类**：`WormAgent`，同样基于 `JointDriveController`/`BodyPart`、`OrientationCubeController`。
  - **核心设计思路**：Crawler/Walker 的**简化版**，用最少的体节演示同一套关节驱动 + 稳定参考系 + 速度/朝向几何奖励的模式，适合作为“如何把物理角色接入 ML-Agents”的最小可运行样板。

### FoodCollector（采集食物，多智能体竞争）
- **目标**：尽量多吃绿色球、避免红色球。
- **智能体数量**：5，独立同构。
- **奖励**：吃绿球 +1；碰红球 -1。
- **观测/动作**：局部速度 + 冻结/发射状态 + 网格感知（`GridSensor`）；3 个连续动作（移动/平移/旋转）+ 1 个离散动作（激光）。
- **变体**：`VisualFoodCollector`（第一人称视觉观测 + 冻结向量标志）。
- **基准奖励**：10。
- **设计说明**：
  - **重要的类**：`FoodCollectorAgent`、`FoodCollectorArea`、`FoodCollectorSettings`、`FoodLogic`。
  - **核心设计思路**：演示**混合动作空间（连续 + 离散）**与**智能体间交互**。移动是连续量，“发射激光”是离散量：激光用 `Physics.SphereCast` 命中其他智能体并调用其 `Freeze()` 使其短暂失能（体现竞争）。
    状态机（冻结/中毒/饱食）用计时器自动恢复并切换材质做可视化反馈。吃到食物在 `OnCollisionEnter` 里加减分，`contribute` 标志可把个人得分汇总到共享分数（用于对比合作/竞争）。`useVectorObs`/`useVectorFrozenFlag` 用于切换向量版与视觉版观测。

### Hallway（走廊记忆任务）
- **目标**：在房间里观察方块颜色，记住它，前往对应颜色的目标。
- **智能体数量**：1。
- **奖励**：正确目标 +1；错误目标 -0.1；每步 -1/MaxStep。
- **观测/动作**：射线感知 + 归一化步数；4 个离散动作（旋转、前后）。
- **特点**：需要记忆（可启用 LSTM）；可加 `curiosity` 奖励信号辅助训练。
- **基准奖励**：0.7。
- **设计说明**：
  - **重要的类**：`HallwayAgent`、`HallwaySettings`。
  - **核心设计思路**：演示**部分可观测 + 记忆（Memory/LSTM）**。关键信息（方块符号 O/X）只在早期可见，之后需靠策略的循环记忆保留；因此观测里刻意只放很少信息（射线 + 归一化 StepCount），迫使网络学会“记住线索”。
    正确/错误目标用 `OnCollisionEnter` 判定并结束回合。它还用 `Academy.Instance.StatsRecorder` 记录 `Goal/Correct`、`Goal/Wrong` 自定义统计到 TensorBoard，是**自定义指标上报**的样板。

### Soccer（足球，自对弈 / 多智能体对抗）
> 该目录包含两个场景，分别是两种玩法。
- **SoccerTwos（2v2）**：两队各 2 名智能体，进球得分（含时间惩罚），进自家门 -1。3 个离散动作分支（前后/侧移/旋转）。使用 MA-POCA + 自对弈。
- **StrikersVsGoalie（2 前锋 vs 1 守门员）**：前锋进球 +1、每步 -0.001；守门员被进球 -1、存活 +0.001。角色异构，观测维度不同。
- **训练配置**：`config/poca/SoccerTwos.yaml`、`config/poca/StrikersVsGoalie.yaml`。
- **设计说明**：
  - **重要的类**：`AgentSoccer`、`SoccerEnvController`、`SoccerBallController`、`SoccerSettings`；`Team`/`Position` 枚举。
  - **核心设计思路**：演示**对抗性自对弈 + 团队组奖励**。`AgentSoccer` 用 `BehaviorParameters.TeamId` 区分蓝/紫队并镜像出生点/朝向，实现两队共享一个可自对弈的策略。
    角色由 `Position`（Striker/Goalie/Generic）决定移动速度与**存在奖励符号**：前锋每步受 `-m_Existential` 惩罚（催促进攻），守门员每步 `+m_Existential`（鼓励守住）。踢球通过 `OnCollisionEnter` 给球施加与 `m_KickPower` 相关的力，`ball_touch` 课程参数在早期鼓励碰球、后期收敛到进球目标。回合与计分由 `SoccerEnvController` 用 `SimpleMultiAgentGroup` 统一管理。

### Walker（人形步行者）
- **目标**：多自由度的人形角色朝目标方向行走而不跌倒。
- **智能体数量**：10，独立同构。
- **奖励**：几何型（平均速度对齐目标 × 头部朝向对齐）。
- **观测/动作**：各肢体位姿/速度/角速度/关节力；连续动作（16 关节的目标旋转 + 力度）。
- **附带**：`Demos/ExpertWalker.demo`。
- **基准奖励**：2500。
- **设计说明**：
  - **重要的类**：`WalkerAgent`，基于 `JointDriveController`/`BodyPart`、`OrientationCubeController`、`DirectionIndicator`。
  - **核心设计思路**：关节驱动范式中**最复杂**的角色（16 个身体部位）。与 Crawler 同构：稳定参考系下采集观测、`matchSpeedReward × lookAtTargetReward` 几何奖励，
    并额外对奖励做 NaN 检查（物理不稳定时抛异常）。`randomizeWalkSpeedEachEpisode` 支持“变速行走”版本，`SetTorsoMass` 用 `EnvironmentParameters` 随机躯干质量做域随机化，也提供专家演示用于 GAIL/BC。

### Pyramids（金字塔，稀疏奖励 / 好奇心）
- **目标**：先找到并按下开关生成金字塔，撞倒后到顶部金砖。
- **智能体数量**：1。
- **奖励**：到达金砖 +2；每步 -1/MaxStep。
- **观测/动作**：射线感知 + 开关状态 + 局部速度；4 个离散动作。
- **特点**：稀疏奖励，常配合好奇心/RND（`config/ppo/PyramidsRND.yaml`）。
- **基准奖励**：1.75。
- **设计说明**：
  - **重要的类**：`PyramidAgent`、`PyramidArea`、`PyramidSwitch`。
  - **核心设计思路**：演示**稀疏奖励 + 内在动机（Curiosity / RND）**。任务被拆成“找开关→按开关→找金字塔→到金砖”的长链条，但只有最后到金砖才有 +2，中间几乎无反馈，纯 PPO 极难探索出来；因此配套 RND/好奇心奖励信号提供内在探索激励。
    唯一暴露给观测的任务进度就是 `PyramidSwitch.GetState()`（开关是否已按），`OnEpisodeBegin` 随机布置开关、金字塔与出生点以避免记忆固定路径。

### Match3（三消游戏）
- **目标**：通过消除棋子最大化得分。
- **智能体数量**：多个独立智能体。
- **奖励**：每消除一个棋子按 `k_RewardMultiplier`(0.01) × 得分累加。
- **观测/动作**：用自定义 **Sensor/Actuator** 定义（`Match3Sensor`/`Match3Actuator`），
  展示如何为非标准网格游戏接入 ML-Agents。
- **基准奖励**：视觉 39.5 / 向量 38.5。
- **设计说明**：
  - **重要的类**：`Match3Agent`、`Match3Board`（棋盘逻辑，实现 `AbstractBoard`）、`Match3ExampleActuator(Component)`、`Match3Drawer`、`Match3TileSelector`。
  - **核心设计思路**：演示**如何为“非移动型/棋盘型”游戏接入 ML-Agents**。棋盘规则完全封装在 `Match3Board`，ML-Agents 侧通过扩展包提供的 `Match3Sensor`/`Match3Actuator` 抽象把“棋盘状态→观测、合法交换→动作 + 动作屏蔽”对接。
    `Match3Agent` 用**显式状态机**（FindMatches→ClearMatched→Drop→FillEmpty→WaitForMove）推进游戏：训练时走 `FastUpdate()` 一步到位并累加消除得分，非训练时走 `AnimatedUpdate()` 带动画。由于不同回合的连锁步数不同，无法用标准 MaxStep，故用 `m_MovesMade` 计数并 `EpisodeInterrupted()` 手动截断。

### Sorter（排序，变长观测）
- **目标**：在圆形房间中按数字升序访问所有编号瓷砖。
- **智能体数量**：1。
- **奖励**：每步 -1/MaxStep；访问正确瓷砖 +1；错误 -1（结束）。
- **观测/动作**：4 维（位置 + 朝向）+ **变长观测（Variable Length Observations）**，1~20 个实体；3 个离散动作分支。
- **特点**：演示 BufferSensor / 变长观测与课程学习（`config/ppo/Sorter_curriculum.yaml`）。
- **设计说明**：
  - **重要的类**：`SorterAgent`、`NumberTile`，核心是 `BufferSensorComponent`。
  - **核心设计思路**：演示**变长观测（Attention/BufferSensor）**。场景中瓷砖数量每回合随机（1~20），传统固定维观测无法表达；`SorterAgent` 把每块可见瓷砖打包成一条固定长度向量
    （20 维 one-hot 编号 + 相对位置 + 是否已访问）并 `m_BufferSensor.AppendObservation(...)`，由策略中的注意力机制处理任意数量实体。任务要求**按升序**访问：`CurrentlyVisibleTilesList` 排序后用 `m_NextExpectedTileIndex` 校验顺序，错序即 -1 结束。瓷砖数量作为课程参数逐步增加。

### DungeonEscape（地牢逃脱，协作 + 牺牲）
- **目标**：多智能体协作逃出地牢；需有智能体击杀巨龙（牺牲自己）掉落钥匙，其余智能体取钥匙开门。
- **智能体数量**：3 个组成一个多智能体组（Multi-Agent Group）+ 1 条按固定模式移动的巨龙。
- **奖励**：任一智能体成功开门逃出，整组 +1（Group Reward）。
- **观测/动作**：射线感知（墙/同伴/门/钥匙/龙/传送门）+ 是否持钥匙；离散动作（前后 / 左右转 / 左右平移）。
- **特点**：MA-POCA 组奖励的典型示例（`config/poca/DungeonEscape.yaml`）。
- **设计说明**：
  - **重要的类**：`DungeonEscapeEnvController`（核心）、`PushAgentEscape`、`SimpleNPC`/`DragonControllerScript`；关键是 `SimpleMultiAgentGroup`。
  - **核心设计思路**：演示 **MA-POCA 的“事后信用分配”与中途退出**。`DungeonEscapeEnvController` 用 `SimpleMultiAgentGroup` 注册 3 名智能体：撞龙的智能体会“被吃掉”而 `SetActive(false)` **中途退出**（POCA 能正确处理没到回合末就消失的成员），
    但它的牺牲让龙掉落钥匙；其他智能体拾取钥匙（`PushAgentEscape.OnTriggerEnter` 置 `IHaveAKey`）并撞门 `UnlockDoor()`，此时给**整组** `AddGroupReward(1)` 并 `EndGroupEpisode()`。这体现了“个体牺牲换取团队收益”的协作学习，只有组奖励、没有个人奖励。

### SharedAssets（共享资源，非独立环境）
- **作用**：被多个 Demo 复用的脚本、预制体与材质，不是单独训练环境。
- **设计说明**：
  - **重要的类**：
    - `JointDriveController` + `BodyPart`：关节角色（Crawler/Worm/Walker）通用的“肌肉式”PD 关节驱动核心。
    - `OrientationCubeController`、`DirectionIndicator`：为关节角色提供稳定的模型参考系与目标方向可视化。
    - `ModelOverrider`：从命令行覆盖模型（`--mlagents-override-model`），供 CI/自动化回归测试与 `WallJump` 多模型切换使用。
    - `GroundContact`、`TargetContact`、`CollisionCallbacks`：着地/触靶/碰撞回调，供奖励与状态判定复用。
    - `ProjectSettingsOverrides`、`AdjustTrainingTimescale`：训练时统一物理/时间缩放等工程设置。
    - `CameraFollow`/`FlyCamera`、`Monitor`、`SensorBase`、`Area`、`TargetController`：观察与调试辅助。
  - **核心设计思路**：把“跨 Demo 重复出现的能力”抽成可复用组件，是本仓库示例保持一致、易扩展的关键；理解这里的类能显著降低阅读各 Demo 的成本。

### Startup（启动辅助，非独立环境）
- **作用**：`Startup.cs` 根据环境变量在批处理/自动化场景中自动加载指定示例场景，主要服务于构建与测试流程。
- **设计说明**：
  - **重要的类**：`Startup`。
  - **核心设计思路**：读取环境变量得到目标场景名并 `SceneManager.LoadScene`，让 CI/命令行构建能在无人工干预下直接进入某个 Demo 场景运行，是自动化测试管线的入口辅助。

## 六、训练配置索引（config/）

| 算法目录 | 用途 |
| --- | --- |
| `config/ppo/` | PPO（最常用），覆盖大多数示例 |
| `config/sac/` | SAC（离策略），3DBall、Walker、Crawler 等 |
| `config/poca/` | MA-POCA（多智能体协作/对抗）：SoccerTwos、StrikersVsGoalie、DungeonEscape、PushBlockCollab |
| `config/imitation/` | 模仿学习（BC/GAIL）：PushBlock、Pyramids、Hallway、Crawler |

训练命令示例：

```bash
mlagents-learn config/ppo/3DBall.yaml --run-id=my_3dball_run
```
