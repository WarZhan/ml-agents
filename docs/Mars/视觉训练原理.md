# 视觉训练原理（以 Visual3DBall 为例）

> 本文解释 ML-Agents 中「只用摄像头画面」训练智能体的原理。以 `Visual3DBall` 为例：它把 `useVecObs`
> 设为 false、`CollectObservations` 不写任何值，改用 **相机传感器（CameraSensor）** 作为唯一观测来源。
>
> 涉及源码：`com.unity.ml-agents/Runtime/Sensors/CameraSensor.cs`、
> `ml-agents/mlagents/trainers/torch/encoders.py`、`config/ppo/Visual3DBall.yaml`。

---

## 一、本质一句话

视觉训练的本质是 **从像素端到端学习（end-to-end deep RL from pixels）**：
把观测从"人工提取的物理量"换成"原始图像"，再让网络里的 **CNN 自己学出等价的特征**。
强化学习算法（PPO）完全不变，变的只是网络的**输入层与前端编码器**。这与 DQN 用像素玩 Atari 是同一思路。

---

## 二、观测从哪来：相机 → 张量

- **向量版 3DBall**：在 `Ball3DAgent.CollectObservations` 里手写 8 个数（平台旋转 + 球相对位置 + 球速度）。
- **视觉版 Visual3DBall**：关闭 `useVecObs`，`CollectObservations` 不写值；观测由挂在 Agent 上的
  `CameraSensorComponent` 生成。

核心逻辑在 `CameraSensor`：每步把相机渲染成一张 `Texture2D`，写入观测张量：

```csharp
// CameraSensor 构造：观测形状由分辨率与通道数决定
var channels = grayscale ? 1 : 3;
m_ObservationSpec = ObservationSpec.Visual(height, width, channels, observationType);
```

- 观测形状是 **`(height, width, channels)`**：彩色 = 3 通道，灰度 = 1 通道。
- 渲染流程：`ObservationToTexture()` 用一张临时 `RenderTexture` 让相机 `Render()`，再 `ReadPixels` 到
  `Texture2D`，最后写进观测张量；训练时可用 PNG 压缩传输以加速。
- 因此策略网络的输入不再是长度 8 的一维向量，而是一张 **H×W×C 的图像**（像素值归一化到 0~1）。

---

## 三、网络怎么处理图像：CNN 视觉编码器

关键在配置里的 `vis_encode_type`：

```13:17:config/ppo/Visual3DBall.yaml
    network_settings:
      normalize: false
      hidden_units: 128
      num_layers: 2
      vis_encode_type: simple
```

网络结构在向量版的基础上，**前面多接了一个 CNN 视觉编码器**：

```
图像 (H×W×C)
   │
   ▼
CNN 视觉编码器  (由 vis_encode_type 指定)   ← 卷积 + 激活，把像素压成特征向量
   │
   ▼
全连接层  (num_layers=2, hidden_units=128)
   │
   ├──► 策略头 (Policy)：输出 2 个连续动作的分布（平台 X/Z 旋转）
   └──► 价值头 (Value)：输出状态价值 V(s)，供 PPO 计算优势
```

对比向量版：向量版没有 CNN，8 维向量直接进全连接层；视觉版只是**在最前面加了 CNN**，其余完全相同。

### 可选的视觉编码器（`EncoderType`）

源码 `ml-agents/mlagents/trainers/settings.py` 定义了四种：

| 取值 | 类 | 结构简述 | 适用 |
| --- | --- | --- | --- |
| `simple`（默认） | `SimpleVisualEncoder` | 2 层卷积（16→32 通道）+ 全连接 | 轻量、最常用（Visual3DBall 用它） |
| `nature_cnn` | `NatureVisualEncoder` | 3 层卷积（32→64→64）+ 全连接（DQN Nature 论文结构） | 中等复杂视觉任务 |
| `resnet` | `ResNetVisualEncoder` | 多个残差块（ResNet） | 复杂视觉任务，最重 |
| `match3` | `SmallVisualEncoder` | 极小 CNN | Match3 等小分辨率棋盘 |

以默认的 `SimpleVisualEncoder` 为例（`encoders.py`）：

```163:177:ml-agents/mlagents/trainers/torch/encoders.py
        self.conv_layers = nn.Sequential(
            nn.Conv2d(initial_channels, 16, [8, 8], [4, 4]),
            nn.LeakyReLU(),
            nn.Conv2d(16, 32, [4, 4], [2, 2]),
            nn.LeakyReLU(),
        )
        self.dense = nn.Sequential(
            linear_layer(
                self.final_flat,
                self.h_size,
                kernel_init=Initialization.KaimingHeNormal,
                kernel_gain=1.41,  # Use ReLU gain
            ),
            nn.LeakyReLU(),
        )
```

即：`Conv(8×8, stride4) → LeakyReLU → Conv(4×4, stride2) → LeakyReLU → 展平 → 全连接`，
把图像压成长度 `hidden_units` 的特征向量，再交给后续全连接层与策略/价值头。

## 四、训练原理：PPO 不变，CNN 端到端一起学

训练流程与向量版**完全相同**：

1. 采集轨迹（观测、动作、奖励）；
2. 用 GAE 计算优势、用 PPO 的裁剪目标计算 loss；
3. **反向传播时梯度一路传到 CNN**——CNN 的卷积核、后续全连接层、策略/价值头是**联合、端到端**训练的。

所以 CNN 不是单独预训练的固定特征提取器，而是**在 RL 奖励信号驱动下，自己学会"从画面里提取对完成任务有用的信息"**。

---

## 五、为什么"只看画面"也能学会

因为图像里**隐含了**向量版手工给出的那些物理量：

| 向量版显式观测 | 视觉版从画面隐式获得 |
| --- | --- |
| 平台 X/Z 旋转 | 画面里平台的倾斜角度 |
| 球相对位置（Vector3） | 球在画面中的像素位置 / 大小 |
| 球速度（Vector3） | ⚠️ 单帧图像**看不到速度** |

CNN 通过大量样本，学会把"平台看起来是斜的、球偏向某侧"这类视觉模式，映射到正确的纠偏动作。

**关键细节——速度信息**：单张静态图片没有速度。向量版把 `m_BallRb.velocity`（3 维）直接喂进去了，
视觉版拿不到。要补回运动信息，通常靠**堆叠多帧观测**（视觉观测的 stacking，等价于向量的 `Stacked Vectors`），
让网络从"连续几帧球位置的变化"里推断速度。这也是纯视觉任务通常更难、需要更大 `batch_size` 的原因。

## 六、与向量版 3DBall 的关键对照

| 维度 | 3DBall（向量） | Visual3DBall（视觉） |
| --- | --- | --- |
| 观测来源 | `CollectObservations` 手写 | `CameraSensorComponent` 渲染 |
| 观测形状 | 8 维一维向量 | H×W×C 图像 |
| 网络前端 | 直接全连接（MLP） | CNN 视觉编码器 + 全连接 |
| 速度信息 | 显式给出（`velocity`） | 需靠堆叠帧隐式推断 |
| `normalize` | true（向量 running normalize） | false（像素固定归一化） |
| `batch_size` | 64 | 256（更大） |
| `max_steps` | 500000 | 400000 |
| 训练难度/算力 | 低，CPU 即可 | 高，更慢、更吃 GPU |

> `normalize: false` 是因为图像走"像素值除以 255"这类固定归一化，而非向量观测那种基于运行统计的
> running normalization——对视觉观测开 `normalize` 没有意义。

---

## 七、小结

- **本质**：把"人来设计状态特征"换成"CNN 从像素自动学特征"，RL 目标函数与优化算法（PPO）不变。
- **网络**：多了一个由 `vis_encode_type` 指定的 CNN 视觉编码器，与策略/价值头端到端联合训练。
- **代价**：观测更原始、维度更高、缺少显式速度，因此更难训、更慢、更吃 GPU；
  好处是**不需要手写观测**，更贴近真实"只有摄像头"的场景。
